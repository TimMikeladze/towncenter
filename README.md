## Data Layer

This project uses DuckDB to query Age of Empires II game data from parquet files:

- **Data Source**: Parquet files in `export/parquet/` directory
- **Images**: Game assets in `export/img/` (gitignored), mirrored into the git-tracked `public/img/`
- **Database**: In-memory DuckDB instance; every parquet file in `export/parquet/` is loaded as a table (19 today)
- **Queries**: React-cached query functions in `src/lib/db/queries/`

### Refreshing Game Data

Civilizations, units, buildings and techs come from
[SiegeEngineers/aoe2techtree](https://github.com/SiegeEngineers/aoe2techtree)
(`data/data.json`, `data/trees/*.json`, `img/`), which tracks the current AoE2 DE patch.
Everything under `export/` is generated — never hand-edit it.

**Prerequisites** (macOS):

```bash
brew install duckdb webp   # duckdb CLI + cwebp; python3 is already on the system
```

**Pull the latest patch:**

```bash
bun run sync-data
```

What it does:

1. Downloads `data.json`, all 53 civ trees and any missing icons into `.aoe2-cache/` (gitignored, reused on later runs)
2. Rewrites the 19 JSONL tables in `export/json/` (including `names` and `strings`, which carry the English display names and help texts)
3. Rebuilds `export/parquet/` from `export/parquet/schema.sql` via the `duckdb` CLI
4. Converts new icons to webp (`cwebp -lossless`), names them by entity id, and mirrors `export/img/` into `public/img/`

**Flags:**

| Flag | Effect |
| --- | --- |
| `--out-dir DIR` | Write the export elsewhere — use this to diff a run before touching the repo |
| `--skip-images` | Data tables only, no icon downloads |
| `--cache-dir DIR` | Override the download cache location (default `.aoe2-cache/`) |

**After a sync:**

```bash
git diff --stat export/json      # see what the patch changed
bun run build                    # static pages are generated from the parquet files
```

New icons land in `public/img/` as untracked files — `git add` them along with `export/`.

Derived fields worth knowing about, in case upstream changes shape:

- Unit/building/tech **availability** per civ comes from the `civs.<Civ>.{Unit,Building,Tech}` lists in `data.json`; the trees also list unavailable (greyed-out) nodes, so they are not a substitute.
- **Ages**, **node types**, **help string ids** and the per-civ **monk suffix** come from the trees.
- **Unique units/techs** are read off the Castle (building 82) nodes: castle-age unique unit, its linked elite upgrade, the age-3 research node and the age-4 row-6 research node.
- **Display names** come from the per-civ tree node `name` fields (`names` table); entities with no node use `NAME_OVERRIDES` in the sync script, falling back to their internal name.
- **Descriptions** are resolved from `language_help_id` against the `strings` table and parsed in `src/lib/game/text.ts`.
- Units with no tech-tree node (packed Trebuchet, dismounted Konnik, the alternate Ratha modes, the duplicate War Chariot) borrow a companion unit's icon via `ICON_ALIASES`; anything still without a picture points at `img/missing.webp`.

### Database Schema

Key tables:
- `civilizations`, `units`, `buildings`, `techs` - Core game entities
- `civ_units`, `civ_buildings`, `civ_techs` - Civilization-specific availability
- `unit_attacks`, `unit_armours` - Combat statistics
- `civ_uniques`, `unit_upgrades` - Special units and upgrades

### Development Database Inspection

In development, inspect the database via API endpoints:

```bash
# List all tables and their schemas
curl http://localhost:3000/api/db/inspect?action=tables

# Get table statistics
curl http://localhost:3000/api/db/inspect?action=stats

# Sample data from a table
curl http://localhost:3000/api/db/inspect?action=sample&table=civilizations

```

`table` is checked against the tables actually loaded in DuckDB; arbitrary SQL is not accepted.

### Patch changelog

`/changes` is generated by diffing the export against an earlier revision of itself:

```bash
python3 scripts/diff-export.py --base HEAD   # writes data/patch-changes.json
```

Run it after a sync, before committing the new export.

## Derived features

- **Counters** (`src/lib/game/combat.ts`) are computed, not curated: damage per hit is resolved
  class-by-class against the defender's armour, turned into DPS via reload time and projectile
  accuracy, and weighted by resource cost. Ships and land units are never matched against each other.
- **Upgrades** (`src/lib/game/upgrades.ts`) fold the blacksmith, university, stable, barracks and dock
  lines into a unit's stats. The export ships no numeric tech effects, so the deltas are the game's
  published values keyed by real tech id; which lines reach a unit is decided by its armour classes,
  the way the engine decides it. Per-civ availability comes from `civ_techs`
  (`src/lib/db/queries/civ-upgrades.ts`), so `/battle` can show that Goths never get Plate Mail.
- **Battle simulator** (`src/lib/game/battle.ts`, `/battle`) resolves stack-vs-stack fights on each
  side's own reload clock: overkill is discarded per hit, accuracy is applied as an expected
  fraction of connecting hits, and an out-ranged side eats free shots while it closes. Kiting after
  contact, collision, blast radius, healing, conversion and terrain are out of scope.
- **Civ bonuses, focus, team bonus and unique tech text** are parsed out of the in-game civ
  description string (`src/lib/game/text.ts`).
- **Matchup win rates and build orders** under `/competitive` are illustrative placeholders from
  `data/`, and are labelled as such in the UI. Everything else comes from the game files.
